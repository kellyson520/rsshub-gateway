# E-Hentai 画廊预处理连续阅读设计

## 背景

当前网关收到 E-Hentai 画廊链接后，会抓取画廊页，提取第一页单图页，再输出一个带“上一页/下一页”链接的单图 HTML。Flare 的全文阅读器对这些链接的处理会跳出当前阅读界面并交给浏览器，无法形成连续阅读体验。

## 目标

- RSS 条目默认打开时，网关预先处理整本画廊。
- 所有成功抓取的图片按画廊页码从上到下连续输出给 Flare。
- 图片使用网关的 `/_gateway/media/` 签名地址。
- 输出 HTML 不包含单图页跳转链接，不依赖 Flare 点击“下一页”。
- 单个页面失败时保留其他成功页面，并在末尾显示失败页码。
- `?view=gallery` 继续保留现有缩略图预览模式。
- 不修改 RSSHub 源码、RSSHub token 语义或 Flare 客户端。

## 非目标

- 不实现浏览器端 JavaScript 翻页或客户端轮询。
- 不把原始 E-Hentai 页面直接交给阅读器清理。
- 不改变 RSSHub 的登录 token、源站认证或外部站点抓取逻辑。

## 方案

### 请求数据流

默认画廊详情请求按以下顺序处理：

1. 校验网关签名并获取原始画廊 URL。
2. 抓取初始画廊页，收集当前页的单图 URL 和画廊分页 URL。
3. 抓取画廊分页，按 DOM 顺序合并并去重所有单图 URL。
4. 以有限并发抓取单图页 HTML，解析每页的标题、页码和原图 URL。
5. 将成功解析的原图转换为 `/_gateway/media/` 地址，并按原始页码排序。
6. 输出一个连续阅读 HTML；每张图片只作为真实 `<img src>` 出现，不包裹 `<a>`。

`?view=gallery` 在第 2 步后直接使用现有画廊预览渲染，不执行全图预处理。

### 连续阅读 HTML

输出保持一个 Readability 候选父容器，结构类似：

```html
<div class="reader eh-image-page">
  <p class="eh-image-title">画廊标题 · 连续阅读 · 共 N 页</p>
  <p class="eh-image-summary">已加载 N / M 页</p>
  <p class="eh-image-content"><img src="/_gateway/media/..." alt="第 1 页"></p>
  <p class="eh-image-content"><img src="/_gateway/media/..." alt="第 2 页"></p>
  <p class="eh-image-warning">第 7 页暂时无法读取</p>
</div>
```

标题和摘要提供正文候选文本，所有图片段落与它们位于同一个父容器内，确保 Flare Readability 不会丢弃图片。连续阅读页面不生成上一页、下一页或原始单图链接。

### 并发、上限和失败处理

- 单图页抓取采用有限并发，默认并发数为 4；输出顺序不受完成顺序影响。
- 默认最多预处理 300 页。超过上限的页码不继续请求，并在末尾以安全文本提示。
- 每个页面独立失败，记录页码和安全的失败原因类别，不输出上游 URL、签名 token 或响应正文。
- 只要至少有一张图片成功，就返回连续阅读页面并附失败提示。
- 如果没有任何图片成功，沿用现有不可用页面和状态码处理。
- 画廊分页和单图页均复用现有上游代理、重试、断路器和目标白名单。

## 模块边界

- `src/adapters/ehviewer.js`：提供画廊分页和单图 URL 的解析能力，负责源站 DOM 规则，不负责网络请求和 HTML 渲染。
- `src/server.js`：协调画廊分页抓取、有限并发单图抓取、失败收集，并把已抓取数据交给阅读器。
- `src/reader.js`：把已解析的单图数据渲染为一个 Readability 兼容的连续阅读页面；不负责抓取网络。
- `test/reader.test.js`：验证连续页面 DOM、签名媒体和无跳转链接。
- `test/server.test.js`：验证画廊分页请求、单图抓取顺序、并发结果排序和部分失败行为。

## 测试与验收

- 单元测试覆盖：多页图片按原顺序输出；图片不在链接内；输出不含上一页/下一页单图链接；媒体地址均为网关签名地址。
- 服务端测试覆盖：画廊分页被读取；重复单图 URL 被去重；单图请求失败不影响其他图片；失败页码显示在末尾；全失败仍返回安全不可用页。
- 全量 `npm test` 通过。
- 生产容器重建后 `/readyz` 返回就绪。
- 通过新鲜画廊请求的 HTML 和 OpenResty 日志确认 Flare 不需要单图跳转即可发起连续的 `/_gateway/media/` 请求。
